## Proposed title

AksharaCheck — Find the letters your website breaks

## Proposed 1,000-character summary

AksharaCheck helps website builders catch broken Hindi and Kannada rendering that ordinary checks often miss. It opens a page in Chromium at phone and desktop widths, collects concrete evidence of issues such as incorrect language tags, split character clusters, clipped marks and overflowing text, then asks BharatCode's model API to explain the finding in English, Hindi and Kannada and propose a restricted repair. Chromium independently retests each repair and marks it verified only when the original issue disappears without hiding, shrinking or displacing text. Reports include original screenshots, repair attempts and provenance. The scanner works without an AI key; BharatCode powers the multilingual explanation and repair workflow. Built with Python, Playwright, React and Vite.

The nine-finding run passed on 31 October 2026 (9 of 9 explained, 4 repairs verified in Chromium), so the summary may say so. Re-check this line if the demo is run again on a later revision.

## Windows release commands

From `C:\Projects\AksharaCheck` (after pulling the merged `main`):

```cmd
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\python.exe scripts\check_bharatcode.py
.venv\Scripts\python.exe scripts\run_ai_demo.py --max-findings 9
start output\ai-demo\report.html
```

Review `output\ai-demo\report.html` and `report.json` for accuracy and privacy. A failed run generates `output\ai-demo\partial\report.html` and must not be presented as a completed AI run.

Once the local fixture report has passed and been reviewed, it can be published **only as a clearly labelled fixture demo**:

```cmd
.venv\Scripts\python.exe scripts\publish_recorded_scan.py output\ai-demo --slug akshara-fixture-demo --title "AksharaCheck controlled demo" --reviewed-public-content --fixture-demo
```

Then scan a permitted public Hindi or Kannada page, review any false positives and private data, and publish it separately without `--fixture-demo`. A scan with zero findings is still a genuine recorded result; do not manufacture failures for a public page.

```cmd
.venv\Scripts\python.exe -m aksharacheck scan https://hi.wikipedia.org/ --lang both --pages 1 --output output\hi-wikipedia
start output\hi-wikipedia\report.html
.venv\Scripts\python.exe scripts\publish_recorded_scan.py output\hi-wikipedia --slug hindi-wikipedia --title "Hindi Wikipedia" --reviewed-public-content
cd web
npm install
npm run deploy:pages
```

This site deployment requires Git credentials and publishes built static files to `gh-pages`; it is not an AI backend deployment. Commit `web/public/samples` through normal Git workflow before the final source release. Open the published reports in a browser and check screenshots/fonts.

## Final Windows fresh-clone QA

Use an empty folder, new virtual environment, installed Chromium, a scan of a permitted public URL, and a local browser to open the generated HTML. Confirm Devanagari and Kannada text render correctly even when offline after generating the report. Test on phone and desktop widths. Inspect links, copyright/attribution, `BharatCode.txt`, no API secrets in the repository, and that the submission URL points to the repo root.

**Do not confuse GitHub Pages with the full app.** The Pages preview offers a browser-side text checker and recorded evidence. Live URL scans need a properly isolated backend; the README says this in "Run the web app locally".
